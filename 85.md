NIP-85
======

可信断言
------------------

`draft` `optional`

某些 Web of Trust 计算需要访问大量 event 和/或计算能力，使其几乎不可能直接在 client 上执行。本 NIP 允许用户将此类计算卸载给声明的可信服务提供者，并让这些提供者发布已签名的 "Trusted Assertion" event，供用户 client 使用。

## 断言事件

Trusted Assertion 始终是 addressable（replaceable）event，其 `d` tag 指向该断言的 "subject"。本 NIP 目前识别四种可执行此类计算的不同目标 "subject"：*pubkeys*、*regular events*、*addressable events* 和 *nip73 identifiers*。每种 subject 类型映射到一种 event kind：

| Subject            | Event Kind     | `d` tag value     |
| ------------------ | -------------- | ----------------- |
| User               | 30382          | `<pubkey>`        |
| Event              | 30383          | `<event_id>`      |
| Addressable Event  | 30384          | `<event_address>` |
| NIP-73 Identifier  | 30385          | `<i-tag>`         |

计算结果保存在预定义 tag 中，这些 tag 的语法和语义由 provider 和 client 约定。

用 web of trust 分数 `89` 对某个 pubkey 排名的示例：

```yaml
{
  "kind": 30382,
  "pubkey": "<service pubkey>",
  "tags": [
    ["d", "e88a691e98d9987c964521dff60025f60700378a4879180dcbbb4a5027850411"], // 目标用户的公钥
    ["rank", "89"],
  ],
  "content": "",
  //...
}
```

Service provider MUST 为不同算法使用不同的 service key；当算法基于某个用户的视角或设置进行个性化时，也包括每个用户一个 key。

## Kind 30382：以用户为主题

已声明以下结果类型：

| Result type             | Tag name               | Tag value format  |
| ----------------------- | ---------------------- | ----------------- |
| Follower Count          | `followers`            | int               |
| User Rank               | `rank`                 | int, norm 0-100   |
| First Post Time         | `first_created_at`     | unix timestamp    |
| Post Count              | `post_cnt`             | int               |
| Reply Count             | `reply_cnt`            | int               |
| Reactions Count         | `reactions_cnt`        | int               |
| Zap Amount Received     | `zap_amt_recd`         | int, sats         |
| Zap Amount Sent         | `zap_amt_sent`         | int, sats         |
| Zap Number Received     | `zap_cnt_recd`         | int               |
| Zap Number Sent         | `zap_cnt_sent`         | int               |
| Avg Zap Amount/day recd | `zap_avg_amt_day_recd` | int, sats         |
| Avg Zap Amount/day sent | `zap_avg_amt_day_sent` | int, sats         |
| Reports Received        | `reports_cnt_recd`     | int               |
| Reports Sent            | `reports_cnt_sent`     | int               |
| Common Topics           | `t`                    | string            |
| Generally active start  | `active_hours_start`   | int, 0-24, UTC    |
| Generally active end    | `active_hours_end`     | int, 0-24, UTC    |

每个 provider 都可以提供自己的方式来计算这些值。例如，某个 trust provider 的 Follower Count 可能会移除用户已 mute 的公钥，而另一个 provider 则保留它们。用户随后可以通过选择与自己观点一致的 provider，决定在偏好的 client 中如何查看这些信息。

## Kind 30383：以事件为主题

Provider 可以使用以下 tag 对单个 event 评分：

| Result type             | Tag name               | Tag value format  |
| ----------------------- | ---------------------- | ----------------- |
| Event Rank              | `rank`                 | int, norm 0-100   |
| Event Comment Count     | `comment_cnt`          | int               |
| Event Quote Count       | `quote_cnt`            | int               |
| Event Repost Count      | `repost_cnt`           | int               |
| Event Reaction Count    | `reaction_cnt`         | int               |
| Event Zap Count         | `zap_cnt`              | int               |
| Event Zap Amount        | `zap_amount`           | int, sats         |

## Kind 30384：以可寻址对象为主题

Provider 可以使用以下 tag 对 addressable event 的所有版本评分：

| Result type               | Tag name               | Tag value format  |
| ------------------------- | ---------------------- | ----------------- |
| Address Rank              | `rank`                 | int, norm 0-100   |
| Address Comment Count     | `comment_cnt`          | int               |
| Address Quote Count       | `quote_cnt`            | int               |
| Address Repost Count      | `repost_cnt`           | int               |
| Address Reaction Count    | `reaction_cnt`         | int               |
| Address Zap Count         | `zap_cnt`              | int               |
| Address Zap Amount        | `zap_amount`           | int, sats         |

## Kind 30385：以外部标识符为主题

Provider 可以使用 [NIP-73](73.md) identifier 对书籍、地点、电影、网站和 hashtag 评分。

| Result type       | Tag name               | Tag value format  |
| ----------------- | ---------------------- | ----------------- |
| Rank              | `rank`                 | int, norm 0-100   |
| Comment Count     | `comment_cnt`          | int               |
| Reaction Count    | `reaction_cnt`         | int               |

NIP-73 `k` tag 也应添加到 event 中。

## 声明可信服务提供者

Kind `10040` 列出用户对每种结果的首选来源。每个 `kind:tag` 后跟 publisher 的 `pubkey`，以及可获取 assertion event 的 `relay`。Service provider 可以按需使用多个 key 和 relay；当算法基于某个用户的视角或设置个性化时，也包括每个用户一个 key。用户可以公开分享这些设置，或通过使用 NIP-44 将 tag 列表 JSON 字符串化并加密到 `.content` 字段中来保持私密。

```js
{
  "kind": 10040,
  "tags": [
    ["<kind:tag>", "<service key>", "<relay hint>"],

    // examples
    ["30382:rank", "4fd5e210530e4f6b2cb083795834bfe5108324f1ed9f00ab73b9e8fcfe5f12fe", "wss://nip85.nostr.band"],
    ["30382:rank", "3d842afecd5e293f28b6627933704a3fb8ce153aa91d790ab11f6a752d44a42d", "wss://nostr.wine"],
    ["30382:zap_amt_sent", "4fd5e210530e4f6b2cb083795834bfe5108324f1ed9f00ab73b9e8fcfe5f12fe", "wss://nip85.nostr.band"],
  ],
  "content": nip44Encrypt(JSON.stringify([
    ["<kind:tag>", "<service key>", "<relay hint>"],

     // examples
    ["30383:rank", "4fd5e210530e4f6b2cb083795834bfe5108324f1ed9f00ab73b9e8fcfe5f12fe", "wss://nip85.nostr.band"],
    ["30384:rank", "4fd5e210530e4f6b2cb083795834bfe5108324f1ed9f00ab73b9e8fcfe5f12fe", "wss://nip85.nostr.band"],
  ]),
  //...
}
```

如果 provider 提供多种算法或某个算法的多个视角，则每个 tag 中列出的 key SHOULD 指向为每个算法或视角创建的 key。

## 最终考虑

Service provider SHOULD 在新信息到达时尽快更新 Trusted Assertion，但仅在每个 event 的内容确实发生变化时更新，以避免重复下载相同信息。

Service provider MAY 通过使用付费 relay 来限制对结果的访问。

在 TA 中，MAY 使用与 `d` tag 值相同的 `p`、`e` 和 `a` tag，为该用户或 event 的 home relay 添加 relay hint。

## 附录 1：Service provider 可发现性

Service Provider SHOULD 为每个 service key 签署一个 kind `0`，说明谁控制该 key，以及当前版本算法的用途。

```yaml
{
  "kind": 0,
  "pubkey": "<service pubkey>",
  "tags": [],
  "content": "{
   \"name\" = \"Vitor's Brainstormer\", 
   \"about\" = \"A Web of Trust algorithm from Vitor's point of view that considers Follows and Mutes, but no reports, and gives extra score points for anyone around Boston\",
   \"picture\" = \"https://brainstorm.com/logo.png\",
   \"website\" = \"https://brainstorm.com\"
  }",
  // other fields...
}
```

希望向用户提供 Service Provider 列表的 client SHOULD：
1. 下载用户关注列表中用户的 kind `10040` event
2. 连接到列出的每个 relay，并下载对应 service key 的 kind `0`
3. 解析 kind `0` 并收集 `website` 属性
4. 加载该 website 的 OpenGraph tag，并将它们显示为可点击项目
