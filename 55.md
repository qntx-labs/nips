NIP-55
======

Android 签名器应用
--------------------------

`draft` `optional`

## 理由

本 NIP 描述了一种 Android signer 与运行在同一设备上的任意 Nostr client 之间进行双向通信的方法，使 client 永远不需要处理用户私钥。signer 是一个 Android 应用；client 可以是另一个 Android 应用，也可以是网页。

## 术语

- **user**：试图使用 Nostr 的人。
- **client**：面向用户、发送签名请求的应用。
- **signer**：持有用户私钥并响应 _client_ 请求的 Android 应用。
- **user-pubkey**：表示 _user_ 的公钥，由 `get_public_key` 返回。
- **package name**：_signer_ 的 Android 包名（例如 `com.example.signer`），由 _client_ 用于寻址后续请求。

本 NIP 中所有 pubkey 都采用十六进制格式。

## 通信方法

_client_ 可以通过三种方式与 _signer_ 通信：

- **Intents**：由 Android client 使用。_signer_ 打开，_user_ 手动批准或拒绝请求，然后结果返回给 _client_。
- **Content Resolver**：由 Android client 使用。在后台运行而不打开 _signer_，但只适用于 _user_ 先前选择记住的权限。
- **Web**：由 Web client 使用。结果通过 `callbackUrl` 返回，或复制到剪贴板。

## 设置

为了检测和调用 _signer_，Android _client_ 必须在其 `AndroidManifest.xml` 中声明 `nostrsigner` scheme：

```xml
<queries>
  <intent>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="nostrsigner" />
  </intent>
</queries>
```

然后它可以检查是否安装了 _signer_：

```kotlin
fun isExternalSignerInstalled(context: Context): Boolean {
  val intent = Intent(Intent.ACTION_VIEW, Uri.parse("nostrsigner:"))
  return context.packageManager.queryIntentActivities(intent, 0).isNotEmpty()
}
```

## 发起连接

1. _client_ 发送 `get_public_key` 请求。
2. _signer_ 响应 `user-pubkey` 及其 `package name`。
3. _client_ 存储二者，并且在 _user_ 保持登录期间 SHOULD NOT 再次调用 `get_public_key`。
4. _client_ 将所有后续请求发送到该 `package name`。

_client_ MAY 在 `get_public_key` 中传递 `permissions` 列表，使 _user_ 可以预授权方法（Content Resolver 用它在后台响应）。每个 permission 是一个带有 `type`（方法名）的对象；对于 `sign_event`，还可以带一个可选的 `kind`：

```json
[{ "type": "sign_event", "kind": 22242 }, { "type": "nip44_decrypt" }]
```

## 方法

每个请求都有一个 `type`（方法名）和一个 payload。payload 在不同传输方式中的传递方式不同（见下文），但语义相同：

| Method              | Payload         | 额外参数                  | 结果                            |
| ------------------- | --------------- | ------------------------- | ------------------------------- |
| `get_public_key`    | _（空）_        | `permissions`             | `user-pubkey`                   |
| `sign_event`        | event JSON      | `current_user`            | 签名和已签名 event              |
| `nip04_encrypt`     | plaintext       | `pubkey`, `current_user`  | ciphertext                      |
| `nip44_encrypt`     | plaintext       | `pubkey`, `current_user`  | ciphertext                      |
| `nip04_decrypt`     | ciphertext      | `pubkey`, `current_user`  | plaintext                       |
| `nip44_decrypt`     | ciphertext      | `pubkey`, `current_user`  | plaintext                       |
| `decrypt_zap_event` | event JSON      | `current_user`            | 解密后的 event JSON             |

- `current_user` 是当前登录到 _client_ 的 `user-pubkey`，采用十六进制格式。
- `pubkey` 是用于加密/解密的另一方公钥，采用十六进制格式。
- `id` 是可选的 client 选择字符串，会在结果中原样返回，用于在不等待的情况下发送多个请求时匹配响应。

## 使用 Intents

payload 是 `nostrsigner:` URI 数据；所有其他参数都是 intent extras。结果通过 `registerForActivityResult` / `rememberLauncherForActivityResult` 返回。

```kotlin
val intent = Intent(Intent.ACTION_VIEW, Uri.parse("nostrsigner:$payload")).apply {
  `package` = signerPackageName        // 仅 get_public_key 时省略
  putExtra("type", "sign_event")
  putExtra("id", event.id)             // 可选，原样返回
  putExtra("current_user", userPubkey)
}
launcher.launch(intent)
```

结果从返回 intent 的 extras 中读取：

| Extra      | 描述                                                     |
| ---------- | -------------------------------------------------------- |
| `result`   | 方法结果（pubkey、signature、ciphertext 等）             |
| `id`       | 请求中发送的 `id`                                       |
| `event`    | 已签名 event JSON（仅 `sign_event`）                    |
| `package`  | _signer_ package name（仅 `get_public_key`）             |
| `rejected` | 当 _user_ 拒绝请求时为 `true`                            |

非 `Activity.RESULT_OK` 的 `resultCode` 表示 _signer_ 失败（例如崩溃），而不是 _user_ 拒绝了请求。当 _user_ 拒绝时，_signer_ 返回 `RESULT_OK`，并将 `rejected` extra 设置为 `true`。

```kotlin
onResult = { result ->
  if (result.resultCode != Activity.RESULT_OK) {
    // signer error (e.g. crash)
  } else if (result.data?.getBooleanExtra("rejected", false) == true) {
    // user rejected the request
  } else {
    val value = result.data?.getStringExtra("result")
  }
}
```

要在不为每个事件重新打开 _signer_ 的情况下签名多个事件，_client_ 添加下面的 flags，_signer_ 返回一个结果数组。_signer_ 必须声明 `android:launchMode="singleTop"` 才能工作。

```kotlin
intent.addFlags(Intent.FLAG_ACTIVITY_SINGLE_TOP or Intent.FLAG_ACTIVITY_CLEAR_TOP)

// signer answers with:
intent.putExtra("results", listOf(Result(package = signerPackageName, result = signature, id = intentId)).toJson())
```

## 使用 Content Resolver

_client_ 查询 `content://<package-name>.<TYPE>`（例如 `SIGN_EVENT`、`NIP44_ENCRYPT`）。查询的 `selectionArgs` 按 `[payload, pubkey, current_user]` 顺序携带 payload 和参数：

```kotlin
val result = context.contentResolver.query(
  Uri.parse("content://com.example.signer.SIGN_EVENT"),
  listOf(eventJson, "", loggedInUserPubkey),
  null, null, null,
)
```

cursor 返回一个 `result` 列（对于 `sign_event`，还会有一个带已签名 event JSON 的 `event` 列）。当出现以下情况时，查询返回 `null`，或存在 `rejected` 列：

- _user_ 没有为此请求启用“记住我的选择”，
- `user-pubkey` 不存在于 _signer_ 中，
- 请求 `type` 未被识别，或
- _user_ 选择始终拒绝此请求（返回 `rejected` 列，此时 _client_ SHOULD NOT 再回退到 Intent）。

```kotlin
if (result == null) return
if (result.getColumnIndex("rejected") > -1) return
if (result.moveToFirst()) {
  val value = result.getString(result.getColumnIndex("result"))
  // for sign_event also: result.getColumnIndex("event")
}
```

Client SHOULD 在本地存储 `user-pubkey`，并避免在用户登录后调用 `get_public_key`。

## 使用 Web 应用

Web client 无法从 intent 接收结果，因此 _signer_ 通过 `callbackUrl` 返回结果（追加到 URL 上），或者如果未给出 `callbackUrl`，则将结果复制到剪贴板。请求是一个 `nostrsigner:` URL，其 path 是 payload，query string 携带参数：

```
nostrsigner:<payload>?type=<method>&pubkey=<hex_pubkey>&callbackUrl=https://example.com/?result=
```

Query 参数：

- `type`：方法名。
- `pubkey`：另一方的十六进制 pubkey（加密/解密方法）。
- `callbackUrl`：_signer_ 追加结果的位置。如果省略，结果会复制到剪贴板。
- `returnType`：`signature` 或 `event`。
- `compressionType`：`none`（默认）或 `gzip`。使用 `gzip` 时，返回的 event 是 `"Signer1"` + Base64(gzip(event json))；这很有用，因为 intent 和 URL 有长度限制。

```js
window.href = `nostrsigner:${eventJson}?compressionType=none&returnType=signature&type=sign_event&callbackUrl=https://example.com/?event=`;
```

> Web 应用可考虑使用 [NIP-46: Nostr Remote Signing](46.md)。使用这里的方法时，Web client 不能在后台调用 _signer_，因此 _user_ 每次请求都会看到弹窗。

### 示例

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>
    <h1>Test</h1>

    <script>
        window.onload = function() {
            var params = new URL(window.location.href).searchParams;
            var result = params.get("event");
            if (result) alert(result);

            var json = { kind: 1, content: "test" };
            var encodedJson = encodeURIComponent(JSON.stringify(json));
            var anchor = document.createElement("a");
            anchor.href = `nostrsigner:${encodedJson}?compressionType=none&returnType=signature&type=sign_event&callbackUrl=https://example.com/?event=`;
            anchor.textContent = "Open External Signer";
            document.body.appendChild(anchor);
        }
    </script>
</body>
</html>
```
